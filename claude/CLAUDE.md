# 全体のルール

- gitの操作はしない。PR作成を依頼する際は簡潔なPRのdiscription例を英語で挙げる
  - `<タイトル>\n\n## Main changes` 配下にリストで目的を含めた簡潔な変更内容を羅列する 
  - Generate withなどの不要な行は表示しない
- 会話は日本語で出力、意図が伝わらない単語や曖昧な表現は避ける

## コードのコメント

- コメントは、その場で読むだけで意味が分かる内容にする
- 計画・決定の文書の番号 (「構築の手順 5a」「決定 7.2」など)、issue・チケットの番号、ほかのファイルやリポジトリのパスなど、別の場所を見ないと分からない参照を書かない
- 理由が要るときは、参照先を示すのではなく、理由そのものを書く
